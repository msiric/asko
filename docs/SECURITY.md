# Security Model

asko is designed with defense-in-depth. Every layer — host, network, container, application — has independent security controls.

## Host Level

### Firewall (UFW)

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow in on tailscale0    # Allow all Tailscale traffic
sudo ufw enable
```

No ports are open to the public internet. All access is via Tailscale.

### SSH

Disable password auth and use `tailscale ssh` exclusively:

```bash
sudo tailscale up --ssh
# Then disable sshd or restrict to Tailscale interface only
```

### Docker Daemon Hardening

Create `/etc/docker/daemon.json`:

```json
{
  "userns-remap": "default",
  "no-new-privileges": true,
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "storage-driver": "overlay2"
}
```

Then restart Docker:

```bash
sudo systemctl restart docker
```

`userns-remap` maps container root to an unprivileged host user, so even if a container escape occurs, the attacker has no host privileges.

## Network Level

### Four Isolated Docker Networks

```
asko_proxy       — Caddy + services that need reverse proxying
asko_backend     — LiteLLM, Ollama, PostgreSQL, SearXNG, Open WebUI
asko_automation  — n8n, LiteLLM, PostgreSQL, WAHA
asko_linguacafe  — LinguaCafe services (fully isolated, profile-optional)
```

Key isolation guarantees:
- **n8n cannot reach Ollama** (only LiteLLM and PostgreSQL via asko_automation)
- **Ollama is never on the proxy network** (no direct browser-to-inference path)
- **WAHA is isolated** on the automation network only (optional, starts only with `--profile whatsapp`)
- **Only Caddy exposes host ports** (80/443)

### Tailscale

All remote access goes through Tailscale (WireGuard-encrypted). No port forwarding, no public exposure.

## Container Level

Every container has:

| Control | Setting |
|---------|---------|
| No privilege escalation | `security_opt: [no-new-privileges:true]` |
| Minimal capabilities | `cap_drop: [ALL]` + only necessary `cap_add` |
| Memory limits | Per-service `deploy.resources.limits.memory` |
| Health checks | Per-service `healthcheck` with interval/timeout/retries |
| Restart policy | `restart: unless-stopped` |
| Read-only filesystem | Caddy runs `read_only: true` |

## Application Level

### n8n
- `N8N_COMMUNITY_PACKAGES_ENABLED=false` — No third-party code execution
- `N8N_NODES_EXCLUDE=["n8n-nodes-base.git"]` — Git node disabled (CVE mitigation)
- `N8N_PUBLIC_API_DISABLED=true` — No public API access
- `N8N_BLOCK_ENV_ACCESS_IN_NODE=true` — Workflows cannot read server environment variables
- `N8N_DIAGNOSTICS_ENABLED=false` — No telemetry (also fixes Ollama performance bug)
- Basic auth required on all access

### PostgreSQL
- Separate database per service (asko_n8n, asko_openwebui)
- Never on the proxy network (no direct browser access)

### LiteLLM
- Master key authentication required for all API calls
- Spend tracking enabled

### Open WebUI
- First user to sign up becomes admin; admin can disable further signups from the UI
- Secret key for session encryption

## Secret Management

- All secrets auto-generated by `setup.sh` using `python3 secrets` module
- `.env` file set to `chmod 600` (owner read/write only)
- `.env` is in `.gitignore` — never committed
- Template files use `${VAR}` references, never actual values

## Keeping Updated

n8n has had multiple critical CVEs (CVSS 9.9-10.0) in late 2025 / early 2026. Always update promptly:

```bash
./scripts/update.sh
```

This runs a backup first, then pulls new images and does a rolling restart with health checks.

## Reporting Issues

If you find a security issue in asko, please open a private security advisory on GitHub rather than a public issue.
